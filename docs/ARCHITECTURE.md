# Fasti 架构说明

> 面向：想理解这个项目为什么这样设计的人（贡献者、未来的自己、其他 Agent）
> 更新于：2026-11-15 · 对应代码 `format_version 3`
> 想看"现在完成到哪了" → 见 [PROJECT-STATUS.md](PROJECT-STATUS.md)

---

## 一句话

**Fasti 是一个本地优先的个人事实台账 + 视图渲染器。**

你记下关于自己的事实（带时间），它维护这些事实的**演进历史**，并渲染成 AI Agent 会读的 Markdown。

---

## 1. 它解决什么问题

每开一个新 AI 会话，你都要重新交代"我是谁、我在做什么、我偏好什么"。

现有的解法有三种，都有问题：

| 解法 | 问题 |
|---|---|
| 每次手动贴一段自我介绍 | 累，而且会忘 |
| 写死在 `CLAUDE.md` 里 | 静态的，改了没历史，看不出"我变了" |
| 让 AI 自己记 | 绑在某个平台，带不走 |

**Fasti 的取舍**：把"关于我的事实"做成一份**带时间维度的台账**，独立于任何 Agent 存在。

核心不是"记住更多事实"，而是：

> **准确表达"这个人现在是谁"，以及"他是怎么变过来的"。**

## 2. 整体分层

```
┌─ 界面层（可替换）──────────────────────────────┐
│  adapters/cli.py    22 个命令                  │
│  adapters/web.py    16 个本机 HTTP 端点         │
│  只调用 core/api.py，不碰存储                    │
└──────────────────┬────────────────────────────┘
                   ▼
┌─ 核心门面 core/api.py ────────────────────────┐
│  20 个应用服务函数，纯 re-export 的薄门面        │
│  适配层唯一允许 import 的入口                    │
└──────────────────┬────────────────────────────┘
                   ▼
┌─ 核心服务 core/services/ ─────────────────────┐
│  facts      事实增删改查                        │
│  categories 类别管理                            │
│  views      画像 / 历史 / 渲染                  │
│  lifecycle  init / status / export / import     │
│  verify     完整性自检                          │
└──────────────────┬────────────────────────────┘
                   ▼
┌─ 基础层 ──────────────────────────────────────┐
│  store      事件日志读写（唯一持久化）           │
│  fold       事件 → 数据模型（纯函数）            │
│  model      领域对象                            │
│  render     确定性渲染                          │
│  validate   四层校验                            │
│  similarity 防重复检测                          │
└────────────────────────────────────────────────┘
```

### 三条硬约束

1. **核心层不 import 界面组件**：`core/**` 不得出现 `argparse` / `http.server` / `sys.argv` / `print`
2. **适配层只走门面**：`adapters/**` 只能 `from fasti.core import api`，不得直接 import `core.services.*`
3. **界面可替换**：从 CLI 换到网页（已做）、换到桌面端，核心层零改动

这两条由测试静态守卫（`test_layering` / 契约测试）。

## 3. 记忆模型（核心设计）

### 3.1 为什么不用一张表

如果直接存"现在的我"：

```sql
UPDATE me SET language = 'C++';   -- 历史没了
```

你会永久失去三样东西：
- 我以前是什么
- 这是**变了**还是**记错了**
- 什么时候变的

### 3.2 事件溯源

Fasti 记的是**发生过什么**，不是**现在是什么**。

```
events.jsonl（只追加）
    │ fold（纯函数折叠）
    ▼
当前事实库 + 当前画像 + 历史时间线
```

**画像不落地为真相**，每次都是从事件现算。所以：
- 删掉所有派生文件，能逐字节还原
- 同一批事件算多少次，结果都一样

### 3.3 两层身份：line 和 fact

| 概念 | 含义 | 例子 |
|---|---|---|
| **line**（命题线） | 一个槽位 / 一个问题 | "我的主力语言是什么？" |
| **fact**（事实段） | 该槽位在某段时间的值 | 2025-01~2026-10 是 Python |

**一条 line 是一条时间轴，fact 是轴上的若干段，时间不重叠。**

```
line 01a1c0ce1c9c  「主力语言」
   ├─ fact(2025-01-01 ~ 2026-10-31)   Python      ← 原始录入
   └─ fact(2026-11-01 ~ 至今)          C++         ← 演进
        └─ revision@2「纠正」：内容改写过，原内容保留
```

**重要**：`line` 没有"属性名"字段，它的身份就是一个 UUID。用户点「变更」时选中的是哪条 fact，系统就顺着它找到对应 line。**这是为什么同一件事可能裂成两条线**（用户如果误用了「新增」），也是为什么"合并两条线"要专门做（P1）。

### 3.4 三种写操作，三种语义

| 操作 | 对 line | 对 fact | 用在哪 |
|---|---|---|---|
| **新增** | **新建**一条线 | 线上放第一段 | 全新的信息 |
| **演进** | 不动 | 同一线**追加**新段（时间必须更晚） | 事情真的变了 |
| **纠正** | 不动 | 同一段**追加修订**（区间不变） | 当初写错了 |

**这个区分是整个产品最核心的价值。** 它让"你以前是 Python 后来转 C++"和"你一直用 C++ 只是之前写错了"成为两条不同的历史。

### 3.5 时间：双时间

| 字段 | 含义 | 例子 |
|---|---|---|
| `valid_from` / `valid_to` | 事实在**现实世界**的生效区间 | 2025-01 起 |
| `recorded_at` | 系统**何时知道** | 2026-11-09 21:32 |

**存储精度**：秒级完整时间戳（RFC3339 带本机偏移）。
**输入接受三档**：`2026-11` / `2026-11-09` / `2026-11-09T23:50:00`，粗输入映射到粒度起点。
**显示自适应**：月起点显示 `2026-11`、日起点显示 `2026-11-09`、有时刻才显示完整。
**同粗粒度桶内再演进**：自动按当前时刻记录并明确提示（`auto_bumped`），用户无需手填时分秒。

### 3.6 ID

UUIDv7（时间有序 + 全局唯一），为将来多设备同步打底。CLI 显示 **12 位短 ID**（完整时间戳，不同毫秒必不同）。

## 4. 存储

### 4.1 六层，只有一层是数据

```
~/.fasti/
├── events.jsonl              ← ★ 唯一真相（逻辑上只追加）
│
│   ↓ fold（纯函数折叠）
│   内存模型（事实库 + 当前画像 + 历史）
│
├── dist/                     ← 派生：给 Agent 读
│   ├── AGENTS.md
│   ├── CLAUDE.md
│   ├── .cursor/rules/fasti.mdc
│   └── INSTALL.md
├── profile/                  ← 派生：给人读
│   ├── current.md                当前画像（含「未录入」占位）
│   └── history.md                历史时间线
├── state/
│   ├── .lock                     写锁（防并发写坏）
│   └── manifest.json             产物指纹（sha256），检测过期/篡改
└── exports/                  ← 迁移用
```

**除 `events.jsonl` 外全部可删重建。** 已实测：删掉 `profile/` 和 `dist/`，跑 `recompute` + `render` 后 sha256 逐字节相同。

### 4.2 事件格式

一行一个 JSON：

```json
{"seq": 9, "at": "2026-11-09T21:32:51+08:00", "type": "fact_created",
 "data": {"fact_id": "01a1c0ce...", "line_id": "01a1c0ce...",
          "category_key": "tech", "content": "主力语言：Python",
          "valid_from": "2025-01-01T00:00:00+08:00",
          "recorded_at": "2026-11-09T21:32:51+08:00",
          "source": "user_entry"}}
```

**事件类型**（8 种）：`store_initialized` / `category_added` / `category_updated` / `category_deleted` / `fact_created` / `fact_evolved` / `fact_corrected` / `fact_deleted`

**注意一个容易误解的点**：文档说"只追加"，但物理实现是**在写锁内全量重写 + 原子替换整个文件**（`store.write_events`）。

- **逻辑上**：只追加，永不修改既有事件
- **物理上**：全量重写，保证原子性和崩溃一致性

`valid_to` / `content` / `revision_count` / `segment_count` 这些字段**不存储**，都是折叠时现算的。

### 4.3 容量

| 项 | 现状 / 上限 |
|---|---|
| 注入给 Agent 的画像 | ~1.2 KB / 建议预算 8 KB（约 90–250 条事实） |
| 事件日志 | 10 万条以内无需索引（实测解析 24MB 约 0.22 秒） |
| 数据库中转 | **没有数据库**。SQLite 只在内存里跑 DDL 做约束校验 |

## 5. 写入与管理

### 5.1 写路径：先校验，后落盘

```
写请求
  → 内存折叠出新状态
  → 四层校验（格式 / 领域不变量 / SQL 约束 / 时间序）
  → 全部通过 → 原子写入 events.jsonl
  → 任一失败 → 什么都不写
```

**已实测**：多次失败的写操作后，`events.jsonl` 的 sha256 完全不变。

### 5.2 治理能力

| 能力 | 实现 |
|---|---|
| 历史版本 | 每次修改都是新事件，旧内容永不覆盖 |
| 来源追溯 | `source` + `recorded_at` + `provenance` |
| 墓碑删除 | 标记删除，历史保留 |
| 确定性重算 | 同一事件流 → 同结果（逐字节） |
| 完整性自检 | `verify --deep` 七项检查 |
| 导出审计 | 确认过的重复新增带 `duplicate_confirmation` 痕迹 |

### 5.3 防重复（两级）

```
命中 = Tier1: 字符相似度 ≥ 0.60
    OR Tier2: 字符相似度 ≥ 0.25 且 共享 ≥2 个英文实体词
```

- **Tier1** 抓措辞接近的（`主力语言：C++` vs `主力语言是C++`，0.85）
- **Tier2** 抓同一主题的改写（长句改写字面只有 0.31，但共享 `python`/`c++`）

命中后服务端返回 `CONFLICT_SIMILAR_FACT` + 一次性确认令牌，用户必须显式确认才能创建。**前端弹窗只是 UX，服务端才是防线**（命令行绕过一样被拦）。

## 6. 记忆怎么被使用

### 6.1 主链路：注入（push）

```
events.jsonl
   ↓ fold
当前画像（内存）
   ↓ render（压缩：去掉「未录入」占位）
~/.fasti/dist/AGENTS.md          ~1.2 KB Markdown
   ↑ 软链
~/.dsh/AGENTS.md
   ↓ DSH 会话启动时自动读取
Agent 的上下文
```

**关键：Markdown 是出口，不是仓库。**

### 6.2 注入点

| 宿主 | 位置 | 方式 |
|---|---|---|
| DSH / Codex 类 | `~/.dsh/AGENTS.md` | 软链（一次放置，所有项目生效） |
| Claude Code | `~/.claude/CLAUDE.md` | 软链（若已存在手写内容则拒绝覆盖） |
| Cursor | 项目级 `.cursor/rules/fasti.mdc` | 降级（无文件形式全局规则） |

### 6.3 三条读取链路

| 链路 | 谁读 | 内容 |
|---|---|---|
| `dist/*` → 软链 | **Agent** | 当前画像（无占位、最省 token） |
| `profile/*` | 人 | 当前画像 + 历史（含「未录入」） |
| `profile at --at <时间>` | 人 | 任意时点回溯 |

### 6.4 一个重要边界

**注入给 Agent 的只有当前画像。** 历史、时点回溯、修订记录都**不进上下文**——因为：
1. 占 token
2. 对当前任务通常是噪音
3. 最容易出错的地方是让模型把"以前"当"现在"

历史要让 Agent 用上，需要检索层（P3）。

## 7. 迁移与换环境

### 7.1 三个层次

**① 同机备份**
```bash
fasti export --out ~/Desktop/备份
# 产出：index.md / profile.md / log.md / README.md / manifest.json
#       concepts/*.md（每条记忆一个 Markdown）
#       data/events.jsonl（★ 权威）
#       data/entities.jsonl（快照）
```

**② 换机器**
```bash
# 1. 拷整个 ~/.fasti
# 2. 重跑 install-host（软链是绝对路径，必须重建）
fasti install-host
# 3. 验证
fasti verify --deep
```

**③ 换实现 / 跨系统**
- `data/events.jsonl` 是权威，Markdown 只是给人看的
- 别的系统**能读**（解析 JSONL）
- 别的系统**不能写回**（导入只认 JSONL，Markdown 不参与）——这是当前能力边界

### 7.2 格式断代

`format_version` 不向后兼容，每次升级要迁移脚本：

| 版本 | 变更 | 迁移脚本 |
|---|---|---|
| v1 → v2 | 序号 ID → UUIDv7；类别 ID → 语义 key | 无（P0 数据量小，清空重建） |
| v2 → v3 | 月精度 → 秒级时间戳 | `scripts/migrate_v2_to_v3.py`（dry-run / 原子 / 幂等） |

当前代码**只接受 `format_version == 3`**。

## 8. 能力边界（明确不做的）

| 不做 | 原因 / 去向 |
|---|---|
| 自动从对话提取 | **即将做**（P1 核心） |
| 语义检索 / RAG | P3；需要时上 SQLite FTS5 + 向量索引（派生，可重建） |
| 云端 / 多设备同步 | 自用单机；ID 已用 UUIDv7 预留能力 |
| 合并两条线 | P1（当前只做提示+确认，不做自动合并） |
| 端到端加密 | 不做云端，无此需求 |
| 桌面端打包 | Markdown + 网页足够 |
