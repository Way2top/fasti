**让系统从你的对话历史里自动认出"值得长期记住的事实"，你只在需要时点几下确认。**

## 完整流程

```
┌─ ① 抽取（LLM，不看数据库）────────────────────────────┐
│  读 ~/.dsh/sessions/**/session.v4.jsonl.zstd          │
│  只取 user/message（助手消息不抽取、不发送）            │
│  按消息边界分块（≤20 条 / ≤4000 字）                    │
│  LLM 输出：候选 {内容, 类别, 时间线索, 抽取置信度}       │
└───────────────────────┬───────────────────────────────┘
                        ▼
┌─ ② 召回（确定性，扫全库）──────────────────────────────┐
│  全库当前事实 ≤ 8KB → full 模式：全量（含已关闭类别）    │
│  全库当前事实 > 8KB → retrieval 模式：每候选 top-K       │
│                       （≤20 条 / ≤6KB）                │
│  判 update/correct 时按需追加同 line 历史段（historical）│
│  每条压缩成一行：短ID | 类别 | current|historical | 内容 │
└───────────────────────┬───────────────────────────────┘
                        ▼
┌─ ③ 判定（LLM，只看「候选 + 召回结果」）────────────────┐
│  输出：relation = new | update | conflict              │
│        target_fact_id（必须来自召回集，否则转审核）      │
│        relation_confidence + 理由                      │
│  prompt 大小恒定，不随库增长                            │
└───────────────────────┬───────────────────────────────┘
                        ▼
┌─ ④ 决策（确定性 + 人工）──────────────────────────────┐
│  见下方决策矩阵                                        │
└───────────────────────────────────────────────────────┘
```

## 五个关键设计点

### 1. LLM 从不看全库

**这是硬约束，不是实现细节。**

理由（我们实测过的）：
- 喂渲染画像 → 盲区大（关闭类别不渲染、历史段不在、预算截断）
- 喂全量事实 → 100 条 15KB、500 条 75KB，不 scale

所以：**第一段只给对话，第二段只给「候选 + 最多 20 条召回结果」**。prompt 大小恒定。

### 2. 召回可以不准，判定负责准

实测标定：纯字符相似度**分不开**「同一件事的改写」和「两件不同的事」

```
应该命中最低值 0.298  ←「目标：通过华为考试」vs「想考华为认证」
不应命中最高值 0.330  ←「夯实C++基础」vs「学习C++设计模式」
→ 区间重叠
```

所以召回**宁滥勿缺**，把相似的都捞回来，让 LLM 判定谁是谁不是。

### 3. 三段防线，冲突时保守

| 层 | 谁 | 作用 |
|---|---|---|
| ① 抽取 | LLM（不看库） | 语义层识别 |
| ② 召回 + 系统相似检测 | 确定性 | 兜字面、防 LLM 失误 |
| ③ 判定 + 人工 | LLM + 你 | 精确区分 + 最终收口 |

**任何一层认为"可能已有关系" ⇒ 绝不自动写入。**

### 4. 自动写入的门槛很高

必须**同时满足四条**：

```
抽取置信度 ≥ 0.85
关系判定 = new（全新）
关系置信度 ≥ 0.80
系统相似检测无命中
```

外加：`auto_write` 开启、未超上限、C-08 防重复未拦截。

**任一条不满足 → 进审核队列。**

### 5. 可解释、可追溯、可关闭

- 候选记录：召回了哪些事实、为什么命中（原因码 + 相似度）
- 运行记录：模式（full/retrieval）、语料大小、是否截断
- 一键关闭（含手动触发也停）

## 决策矩阵

| 情况 | 处理 |
|---|---|
| 类别不存在 / 内容非法 / 无用户消息证据 | 丢弃 |
| 敏感内容（打码占位 / 命中敏感规则） | 丢弃 |
| 证据已处理过（幂等） | 跳过 |
| **高置信 + 判全新 + 系统无相似 + auto_write 开 + 未超限** | **自动写入** |
| 判 update / conflict | **审核**（update 通过时必须显式选演进或纠正） |
| 系统相似命中（即使 LLM 说全新） | **审核**（保守） |
| 低置信（抽取<0.45 或关系<0.50） | **审核** + 低置信标记 |
| auto_write 关闭 | **全部审核** |
| 超过上限（每次 10 / 每日 20） | 转审核 |

| 项 | 变化 |

**你的数据需要再迁移一次**（第三次）。有脚本 + 备份 + dry-run。

## 隐私与安全

| 项 | 做法 |
|---|---|
| 发给外部 LLM 的内容 | A 段：仅用户消息；B 段：候选 + 召回事实（≤6KB） |
| 敏感打码 | 默认开：密码/密钥/token 发前打码 |
| 告知 | **一次性同意**，文案说明"会话内容 + 相关已有事实会发送" |
| 配置存储 | `~/.fasti/config.json`，权限 600 |
| 运行记录 | 只含计数/失败码/session_id，**不含原文、不含密钥** |
| 关闭 | 一键停用，含手动触发 |

## 成本估算

每次提取大约两次 LLM 调用链：

| 环节 | 输入量 | 说明 |
|---|---|---|
| A 段（抽取） | 每个消息块 ≤4000 字（约 6K token） | 一段对话通常 1 块 |
| B 段（判定） | 每个候选约 3000 token（候选 + ≤6KB 召回） | 假设 5 个候选 |

单次运行约 **2–3 万 token**，用 `deepseek-flash` 粗估 **每次几分钱**。

按每天 10 次自动触发算，一个月几块钱。**超了会很明显，届时可以调低触发频率。**

## 已知边界与风险

| # | 风险 | 兜底 |
|---|---|---|
| 1 | **召回可能漏**：措辞差异极大的语义重复捞不到 | 中文保守检查 + 人眼（画像才几十条）+ 未来做"定期两两巡检" |
| 2 | 高置信自动写仍可能误判 | 可关闭 `auto_write`（全走审核）；每条可追溯来源 |
| 3 | LLM 输出格式非法 | 拒收，不写入，水位不前进，可重试 |
| 4 | 会话文件损坏 | 跳过并记录，不中断整次运行 |
| 5 | 隐私：对话内容外发 | 一次性告知 + 打码 + 可关闭 |
| 6 | 成本随使用量增长 | 触发节流 60s + 每次/每日上限 |

## 实现与验收

**规模**：29 核心函数 / 31 CLI 命令 / 26 web 端点 / 66 错误码 / 102 条 AC

**新增能力**：
- CLI：`fasti extract`（手动）、`fasti extract status`、配置命令
- 网页：待审队列、提取运行记录、配置与开关
- 数据结构：候选、水位、运行记录

**验收要点**：
- 两段 prompt 内容分别断言（A 段**不得**出现任何 fact/召回数据）
- 召回：小库 full 含关闭类别 / 大库 retrieval + 截断标记
- 幂等、水位重建、坏会话跳过
- LLM 失败三态（非法结构/超时/断网）均不写入、水位不前
- 隐私打码与运行记录无原文
